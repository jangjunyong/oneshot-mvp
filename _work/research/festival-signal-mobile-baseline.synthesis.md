# 종합: 이동통신 시군구 일별 체류인구만으로 축제 효과 유무를 판별·표시하는 기준과 방법론

## 쟁점 목록

### 쟁점 1. 공공 서비스는 "축제 효과"를 무엇과 비교하는가 (비교 기간·베이스라인 정의)

- 합의: [1차] 한국관광데이터랩은 축제 효과를 "각 연도별 축제기간과 비축제기간(축제 전후 4주간)의 지표 차이"로 정의한다 — 근거: docs F1. academic F8 도 같은 취지("전후 4주")를 적었으나 스니펫만 본 `[추정]` 이라 등급을 올리지 않는다.
- 합의: [1차] 공개된 공공 서비스 페이지에는 그 비교에 쓰는 통계적 판정식(z-score·문턱값·유의수준)과 요일 보정 방식이 적혀 있지 않다 — 근거: docs F1(데이터랩), docs F7(서울시 빅데이터 분석 서비스: 기간·영역을 설정하면 자동 비교하지만 비교 기준 기간·판정 기준은 적혀 있지 않음).
- 합의: [1차] 축제 성과 평가에서 방문객 수 자체(일평균·예산 대비)를 기준 축으로 쓰는 사례가 있다 — 근거: docs F2(데이터랩 인터뷰: 예산 대비 방문객·일평균 방문객으로 성공/실패 군집 구분), academic F5(593개 축제 방문객 수 예측 모형, 방문객 수를 성과 기준으로 삼음). 두 출처 모두 개별 축제·개별 연도의 신호 유무를 이진 판정하는 방식은 아니다(docs F2 메모, academic F5 메모).
- ⚔ 충돌: 세 노트 안에서 비교 기간 값 자체를 서로 다르게 말한 사례는 없다. academic F2(한국관광공사 2013 보령머드축제, [2차])의 "평상시 일평균" 은 평상시의 기간 정의가 노트에 없어서 docs F1 의 "전후 4주" 와 같은지 다른지 대조할 수 없다. 사실확인도 원문(울산발전연구원 이슈리포트)에 "평상시" 기간 정의가 없다고 적었다(factcheck C4). 해소하지 않음.
- 공백: 문화체육관광부 "문화관광축제 방문객 통계 산출 가이드라인" 원문(평소 대비 증가분 계산식·비교 기간)은 docs·academic 렌즈 모두 찾지 못했다(docs "찾지 못한 것", academic "찾지 못한 것"). "전후 4주" 창 안의 요일 구성, 다른 행사·공휴일이 겹칠 때의 처리, 전년 동기 비교 병행 여부는 어느 노트에도 없다.

### 쟁점 2. 분모·집계 대상 정의 (현지인·외지인·외국인, 방문객 식별, 공간 단위)

- 합의: [1차] 이동통신 데이터 기반 관광 연구에서 방문객은 흔히 거주자(와 통근자 등)를 식별해 뺀 나머지 집단으로 도출되고, EU 방문객 정의(Regulation 692/2011)는 이동통신 데이터에 드물게 적용된다. 이는 연구 관행에 대한 서술이며, 직접 식별이 불가능하다는 주장은 아니다 — 근거: academic F4(원문 표현 "rarely applied", "often derived as a residual group" — factcheck C10), academic F7(실거주지가 제주 외부인 이용자=방문자), academic F2([2차] 관광가능인구=해당 지자체 인구를 뺀 외부 유입인구의 일별 합).
- 합의: [2차](이해관계) 국내 통신사 상품은 축제 방문객을 현지인/외지인, 외국인(국적별)으로 나눠 제공한다고 적었다 — 근거: docs F6(KT TrIP 영업 브로슈어, 요금표 포함, 24시간 이후 유출은 시군구 단위). 구분 산식은 문서에 없다(docs F6 메모). **이해관계 단독.**
- ⚔ 충돌(정의 층위): 법률상 "생활인구" 는 주민등록인구+체류인구+외국인으로 거주자를 포함한다(docs F3, [1차]). 반면 2013 한국관광공사 축제 분석의 "관광가능인구" 는 해당 지자체 인구를 뺀다(academic F2, [2차]). 두 정의는 쓰임새(법적 인구 집계 vs 축제 성과)가 다르다. 해소하지 않음.
- 시점 차이(충돌 아님, 선후 미확정): 2013년 한국관광공사 축제 성과분석에는 SKT 유동인구 데이터를 썼다(academic F2, 원자료 2013, 이슈리포트 2015-10-16). KT 브로슈어는 KT 데이터를 "한국관광공사 '관광 데이터랩' 단독 공급"한다고 적었고, 공급 대상을 내국인 등으로 한정하지 않았다(docs F6, factcheck C7; 브로슈어 본문에 발행일 없음, 파일명 20230901 기준 2023년 배포 추정). 2023-03-21 보도는 데이터랩이 기존에 KT 데이터만 쓰다가 SKT 데이터도 쓰게 됐다고 적었다(factcheck C7 반대 증거, discoverynews 2023-03-21). 브로슈어 발행일을 확정할 수 없어 두 자료의 선후는 확인되지 않았다(factcheck C7 반대 증거). docs F1 메모의 "KT(내국인)·SKT(외국인)" 는 스니펫 기준이고, 사실확인에서도 데이터랩 해당 페이지에는 통신사명 없이 이동통신·신용카드·내비게이션이라는 데이터 종류만 적혀 있었다(factcheck C1).
- 공간 단위: [2차] 같은 축제에서 지자체 전체 유입 증가율은 29.4%, 축제지점 반경 1.5km 이내는 100.1% 로 나왔다 — 근거: academic F2(단일 사례).
- 공백: 체류인구의 구체 요건(체류 시간·횟수, 이동통신 데이터 처리 산식)이 담긴 행정안전부고시 제2023-33호 원문은 열리지 않았다(docs F3 메모). "현지인·외지인" 을 어떤 거주지 판정 규칙으로 가르는지는 KT 쪽 문서에 없고(docs F6), 대회 데이터 사용자도 정의를 헷갈려했다(community F3). 기지국 기반 현지인/외지인 구분의 정확도를 수치로 지지하거나 반박한 자료는 세 노트에 없고, 사실확인의 추가 검색에서도 찾지 못했다(factcheck C19 반대 증거). 외국인 체류인구로 축제 신호를 판별한 사례는 어느 노트에도 없다.

### 쟁점 3. 요일·계절·공휴일 보정 방식

- 합의: [1차] 학술 출처들은 주간 주기를 모델에 명시적으로 넣는다 — 근거: academic F1(중앙값 기반으로 추세·주간 계절성·DST/공휴일 성분 분해), academic F3(셀·서비스별 주간 중앙값 시그니처 + Butterworth 평활 / Prophet + 주간 주기·학교방학 회귀변수), academic F7(계절별 1주씩 뽑아 대표 평일(수)·대표 주말(토) 비교).
- 합의: [1차] 공휴일·방학은 요일과 따로 성분이나 변수로 다룬다 — 근거: academic F1(DST/공휴일 성분), academic F3(공휴일·학교방학 별도 변수).
- 합의: [1차] 공개 서비스·상용 문서는 요일 보정 계산법을 밝히지 않는다 — 근거: docs F1(데이터랩, 요일 보정 미기재), docs F4(SafeGraph `visits_by_day` 요일 배열은 있으나 보정 계산 설명 없음).
- ⚔ 충돌: 없음. 학술 출처 셋의 보정 방식은 서로 다르지만(academic F1 분해 / F3 시그니처·Prophet / F7 대표일) 서로를 반박하지 않고, docs 렌즈는 방식을 기재하지 않아 대조할 값이 없다(docs F1, F4).
- 공백: 전년 동기 대비 비교와 STL 을 명시적으로 적용한 출처는 세 노트 발견 사항에 없다. 다년(연 단위) 계절성을 다룬 사례도 없다. 학술 출처의 데이터 기간은 지표당 약 60일 자료를 40,320점(4주) 배치로 나눠 적용한 것(academic F1, 배치 크기는 factcheck C11 정정), 3개월(academic F3, 2019-03-15~06-15), 2022년 4개 주(academic F7)다.

### 쟁점 4. 판정 문턱값·유의성 표시와 오탐·미탐 기준

- 합의: [1차] 이상치가 문턱값을 오염시키지 않도록 중앙값 계열의 강건 통계를 쓴다 — 근거: academic F1(ESD 통계량에 평균·표준편차 대신 중앙값·MAD), academic F3(Signature 방식의 중앙값 기반 베이스라인).
- 합의: [1차] 제시된 문턱값은 전부 도메인 밖(IT 지표·도시 이벤트) 학술 출처에서만 나오고, 공공·상용 문서에는 문턱값이 없다 — 근거: academic F1(일반화 ESD, α=0.05, 이상치 약 2% 가정, IT KPI), academic F3(μ+2.32σ / Shewhart μ+3σ, 파리 도시 이벤트) / docs F1, F4, F5, F6, F7(판정식·임계값 미기재), academic F7(국내 제주 사례에도 이벤트 판별 기준 없음).
- ⚔ 충돌: 출처끼리의 충돌은 없다. 문턱값이 방법마다 다를 뿐이다(academic F1 α=0.05 vs academic F3 μ+2.32σ·μ+3σ). 한 출처 안에서 목표치와 실측치가 어긋난 사례가 있다: academic F3 Signature 방식은 상위 1% 를 목표로 했으나 실제 약 3% 가 나왔다고 노트에 적혀 있다. 해소하지 않음.
- 공백: CUSUM 을 관광·축제 방문자에 적용한 논문은 찾지 못했다(academic "찾지 못한 것"). DID·synthetic control 을 이동통신 이벤트 분석에 썼는지는 확인되지 않았다(academic F6 메모: 초록에서 방법론 명칭 미확인). 정답 라벨(실제 축제 효과 유무)로 오탐·미탐률을 잰 사례, 시군구·일 단위 해상도에서 문턱값을 정한 사례는 세 노트 어디에도 없다. academic F3 의 심각도 3단계(4시간·1일·1주 단위 초과 빈도)가 오탐·미탐 기준 설정 방식으로 노트에 나온 유일한 사례다.

### 쟁점 5. 해외 상용 서비스(Placer.ai·Near·Unacast·SafeGraph)의 이벤트 영향 분석

- 합의: [1차] SafeGraph·Unacast 공식 문서는 방문 정의와 지표만 제공하고 베이스라인·이벤트 유의성 판정은 설명하지 않는다 — 근거: docs F4(SafeGraph: 4분 이상 체류해야 방문으로 집계, 정규화 컬럼은 있으나 baseline·임계값 설명 없음), docs F5(Unacast: 하루 동안 해당 장소에 머문 고유 인원을 ML 모델로 추정, 베이스라인·이벤트 탐지 설명 없음).
- 합의: [1차] 실사용 후기에도 "베이스라인 대비 유의한 증가" 판정 방식에 대한 서술은 없다 — 근거: community F4(이벤트 방문자·출발지·이후 행동 확인 기능만 언급).
- ⚔ 충돌: Placer.ai 로 이벤트 방문자를 파악해 쓰고 있다는 사용자 리뷰가 있다(community F4, [1차] 노트 표기, (이해관계) n=1, 2025-03). 반면 Placer.ai 는 정확할 때도 있지만 "way off" 일 때도 있다는 포럼 글도 있다(community F5, [추정] 스니펫만 확인, n=1, 게시일 ?). 해소하지 않음.
- 공백: Placer.ai·Near 의 이벤트 분석 방법론 공식 문서·백서는 docs·academic 렌즈 모두 찾지 못했다(docs "찾지 못한 것", academic "찾지 못한 것"). Reddit·G2 의 실사용 논쟁은 검색 도구 한계와 403 차단 때문에 확보하지 못했다(community "찾지 못한 것"). SafeGraph 데이터를 쓴 학술 연구의 유의성 기준도 확인하지 못했다(academic F6 메모).

### 쟁점 6. 원천 데이터 품질·표본이 신호 판별의 전제로 믿을 만한가

- 합의: [1차] 원시 위치 신호의 상당 부분이 걸러진 뒤에 집계·추정된다 — 근거: community F1(광고·GPS 위치 데이터 업계 실무자: 하루 60~75% 를 버림, 2019-02-26, n=1), docs F5 메모(Unacast methodology 페이지: 중복·오류 제거 최대 65%, 방문은 ML 모델 추정). 두 출처 모두 통신사 기지국 데이터가 아니다(community F1 메모, docs F5).

## 미해결·공백

- 문화체육관광부 "문화관광축제 방문객 통계 산출 가이드라인" 원문, 곧 이동통신 기준 "평소 대비 증가분" 계산식과 비교 기간 공식 정의를 확보하지 못했다. docs 는 문체부 공식 도메인 원문을 찾지 못했다(docs "찾지 못한 것", 제3자 업로드 편람은 docs "검색 한계"). academic 이 찾은 「2022 문화관광축제 빅데이터 분석 사업」 HWP 는 인코딩 문제로 열리지 않았다(academic "찾지 못한 것"·"검색 한계").
- 한국관광데이터랩 "5대 지표" 의 정의와 산출식은 1차 문서로 확인되지 않았다(academic F8, academic "찾지 못한 것"). 사실확인에서도 해당 페이지는 5대 지표를 정의하지 않고 "데이터 설명" 항목을 보라고만 안내했으며, 데이터 설명 페이지에도 축제 산출식이 없었다(factcheck C2). 확인 경로로 적힌 보고서들(2024 문화관광축제 빅데이터 분석 용역 최종보고서 — academic F8 메모, 2023 문화관광축제 빅데이터 분석 보고서 게시물 — community "검색 한계")은 어떤 렌즈도 본문을 열지 않았다.
- 2013 보령머드축제 분석의 "평상시" 가 어떤 기간인지는 노트에도 원문 이슈리포트에도 없다(academic F2, factcheck C4).
- 체류인구 세부요건 고시(행정안전부고시 제2023-33호) 원문의 체류 시간·횟수 기준은 열리지 않았다(docs F3 메모). "월 1회, 하루 3시간 이상" 수치는 스니펫에만 있어 노트가 인용하지 않았다(docs F3 메모).
- 기지국 기반 현지인/외지인 구분 정확도를 수치로 다룬 자료는 세 노트에 없고, 사실확인 추가 검색에서도 찾지 못했다(factcheck C19 반대 증거). KT 브로슈어는 구분 산식을 싣지 않았고(docs F6), 대회 참가자도 변수 정의를 질문했다(community F3).
