# FLOW — 흐름 · 실패 경로 · 도구 선택

## 흐름 한 장

```
[입력] 기획안 텍스트 붙여넣기 → 뽑힌 항목 확인·수정
   │    항목 = 지역 · 시기 · 테마 · 인구 · 접근성
   ▼
[파싱] 항목이 빠졌으면 ─────────────▶ 무엇이 없는지 짚어 되물음
   │   (지금은 사람이 직접 채운다)
   ▼
[닮은 축제 탐색] 특징 벡터 → 거리 계산 → 상위 3개
   │
   ├── 임계값 넘음 ──────────────▶ "비교 대상 없음" + 찾아본 범위 → 끝
   ▼
[경보 등급] 닮은 3곳의 방문 배수 중앙값
   │
   ├── 근거 약함 ────────────────▶ "위험 근거 못 찾음" (안전 아님)
   ▼
[출력] 등급 · 한 문장 · 왜 닮았나(축별) · 그들이 겪은 것(출처 포함)
```

**상태는 없다.** 한 요청이 한 번에 끝나고 노드 사이를 흐르는 것이 없다.

## 실패 경로

강의: *"에이전트 설계의 대부분은 실패 설계입니다. 정상 경로는 원래 쉽습니다."*

| 이런 일이 생긴다 | 정해두지 않으면 | 이 제품의 처리 |
|---|---|---|
| 답을 모른다 — 닮은 축제가 없다 | 억지로 가장 가까운 걸 내놓는다 | **"비교할 만한 과거 축제가 없습니다"** + 찾아본 범위. 임계값 넘으면 뺀다 |
| 도구가 죽거나 시간이 초과된다 | 전체가 멈춘다 | 1회 재시도 → 정적 데이터만으로 **축소 응답** + "일부 확인 실패" 배지 |
| 같은 행동을 반복한다 | 토큰만 쓰며 무한 루프 | 파싱 되물음은 **1회까지.** 그 뒤엔 받은 것만으로 진행 |
| 입력이 예상을 벗어난다 | 500 으로 끝난다 | 지역명 모호 → 후보 제시하고 되물음. 항목 누락 → 무엇이 없는지 짚음 |

## 프레임워크: 쓰지 않는다

**지금은 함수다.** 입력에서 출력까지 분기가 없다. 강의: *"2주 MVP는 대부분 여기에 해당합니다. 모르겠으면 함수부터."*

랭체인·랭그래프를 살 만한 순간 셋 중 **하나도 해당하지 않는다** — 재시도는 1회뿐이고, 상태가 아예 없고, 사람 개입은 되물음 1회다. **SDK 직접 호출과 함수 몇 개면 충분하고 이 코드는 내가 읽을 수 있다.**

**RAG 도 쓰지 않는다.** 축제 기록은 구조화된 필드로 들어온다. 문서를 검색해 답을 만드는 구조가 아니라 임베딩·벡터DB·청킹이 들어갈 자리가 없다.

에이전트가 되는 지점은 하나 — **기획안마다 문제되는 위험축이 다르고, 어느 축부터 볼지를 모델이 정할 때.** 우기지 말고 잰다. 실제 기획안 여러 개로 돌려 **모델이 보는 축의 개수와 순서가 입력마다 달라지는지** 확인하고, 항상 같으면 워크플로우로 확정한다. 결과는 이 절에 숫자로 덮어쓴다.
