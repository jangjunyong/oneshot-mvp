# FLOW — 흐름 · 실패 경로 · 도구 선택

## 1. 함수인가 워크플로우인가 에이전트인가

**지금은 함수다. 그리고 그게 맞다.** 강의 p22~23: *"2주 MVP는 대부분 여기에 해당합니다. 모르겠으면 함수부터."*

| 설계 | 판정 |
|---|---|
| 기획안 → 거리 계산 → 닮은 축제 3개 → 경보 등급 | **함수** ← 오늘 |
| `if (닮은축제 == 0) 조건완화후재탐색()` 을 코드로 | 워크플로우 |
| 모델이 "어느 위험축부터 볼지 / 얼마나 팔지" 결정 | 에이전트 |

LLM 이 꼭 필요한 곳은 둘 — **자연어 기획안 파싱**과 **보완점 문장 생성**. 둘 다 1회 호출이고 루프가 아니다. 그래서 아직 에이전트가 아니다.

**판정 방법 (Day 8):** 우기지 말고 잰다. 실제 기획안 여러 개로 돌렸을 때 **모델이 보는 축의 개수와 순서가 입력마다 달라지는가.** 항상 같으면 워크플로우로 확정한다. 결과는 이 절에 날짜와 숫자로 덮어쓴다.

## 2. 정상 경로

```
[입력] 기획안 텍스트를 붙여넣고, 뽑힌 항목을 확인/수정
   │    항목 = 지역 · 시기 · 테마 · 인구 · 접근성
   ▼
[LLM 파싱] ── 항목이 빠졌으면 ─▶ 무엇이 없는지 짚어 되물음      ★ Day 8
   │    오늘은 이 단계가 없다 — 사람이 항목을 직접 채운다
   ▼
[닮은 축제 탐색]  특징 벡터 → 거리 계산 → 상위 3개
   ├── 없음 ──▶ "비교 대상 없음 + 찾아본 범위" 로 종료
   ▼
[경보 등급]  닮은 3곳의 방문 배수 중앙값으로 매긴다
   ▼
[출력]  등급 · 한 문장 · 왜 닮았나(축별) · 그들이 겪은 것(출처 포함)
```

**상태는 없다.** 한 요청이 한 번에 끝난다. 이것도 아직 에이전트가 아니라는 증거다.

## 3. 실패 경로

강의 p26: *"에이전트 설계의 대부분은 실패 설계입니다. 정상 경로는 원래 쉽습니다."*

| 이런 일이 생긴다 | 정해두지 않으면 | 이 제품의 처리 |
|---|---|---|
| 닮은 축제를 못 찾음 | 억지로 가장 가까운 걸 내놓음 | **"비교할 만한 과거 축제가 없습니다"** + 찾아본 범위. 임계값 넘으면 뺀다 |
| 위험 근거를 못 찾음 | "안전합니다" 라고 말함 | **"위험 근거 못 찾음".** 안전 판정은 하지 않는다 |
| 외부 API 타임아웃 | 전체가 멈춤 | 1회 재시도 → 정적 데이터만으로 축소 응답 + "일부 확인 실패" 배지 |
| 입력이 예상을 벗어남 | 500 으로 끝남 | 지역명 모호 → 후보 제시하고 되물음. 항목 누락 → 무엇이 없는지 짚음 |
| 기획안 텍스트가 너무 김 | 토큰 초과로 에러 | 앞부분만 파싱하고 잘렸음을 알린다 |

## 4. 프레임워크: 쓰지 않는다

랭체인·랭그래프 없이 간다. 강의 p24 기준 셋 다 해당 없음 — 재시도 1회뿐이고, 상태가 아예 없고, 사람 개입은 되물음 1회다. **SDK 직접 호출과 함수 몇 개면 충분하고 이 코드는 내가 읽을 수 있다.**

## 5. RAG: 쓰지 않는다

축제 기록은 **구조화된 필드**로 들어온다. 문서를 검색해 답을 만드는 구조가 아니라 임베딩·벡터DB·청킹이 들어갈 자리가 없다. 강의 p25 의 RAG 실패 3종이 구조적으로 발생하지 않는다.
