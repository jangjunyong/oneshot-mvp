## 작업 규약 (HANDOFF "작업 규약" 절 그대로, 특히)

- 코드를 건드리면: 순수 함수 TDD → 화면 → npm test·typecheck·lint·build·test:e2e
  → 크롬 확인 → 커밋. push 는 검증 5단계가 전부 초록일 때만.
- 화면 문구에 em-dash(—) 쓰지 마라. 한 문장에 strong 하나 이하.
- 크롬 자동화는 JS .click() 으로. 검증은 DOM 텍스트를 읽어서.
- 진단서를 건드리면 인쇄 높이를 다시 재라(방법은 HANDOFF 작업 규약에 코드째 있다).

막히거나 판단이 필요하면 임의로 정한 뒤 docs/DECISIONS.md 에 근거를 남겨라.

## 이 프롬프트를 쓸 때 알아 둘 것 (붙여넣지 말 것)

- **왜 방침이 바뀌었나**: "문서·제출물은 하지 않는다"는 서비스를 끝내려고 둔
  임시 규칙이었다. 서비스가 끝났으므로 근거가 사라졌다. HANDOFF 의 "하지 않기로
  한 것"에서도 그 줄을 뺐다.
- **캡처를 1번에 둔 이유**: 문서 작업의 입력이라서다. 캡처가 낡은 채로 문서를
  쓰면 문서를 두 번 쓰게 된다.
- **"이 절을 어떻게 쓸지 먼저 보여줘"라고 적은 이유**: `#사전 수요 예측` 을
  어떻게 다루느냐가 이번 제출물에서 가장 위험하고 가장 값어치 있는 한 칸이다.
  에이전트가 혼자 정할 자리가 아니다.
