```
oneshot-mvp 이어서 작업. 먼저 개별프로젝트/oneshot-mvp/docs/HANDOFF.md 를 읽고,
이어서 docs/DECISIONS.md 의 "하지 않기로 한 것"만 훑어. 그게 이 프로젝트의 전제다.

방침: 기능이 조잡해도 생각한 대로 완성하는 데 집중한다.
- 새 기능·새 아이디어를 벌이지 마라. 이미 벌인 것을 끝까지 잇는 일만 한다.
- 서비스 개발만 본다. 문서·제출물 작업은 하지 않는다.
- 모바일은 범위 밖이다.

할 일은 HANDOFF 의 "다음 할 일" 네 가지다. 1번부터 순서대로 간다.

1. 시연 세트를 코드로 고정 (제일 급하다)
   지금 서버를 새로 띄우면 진단 이력이 0건이라 화면이 텅 빈다.
   진단서 근거 3(도면 쏠림)도 도면을 따로 저장해야만 채워져서, 시연할 때마다
   손으로 만들어야 한다.
   이력이 비었을 때 시연용 진단 1건 + 연결된 도면 1건이 있는 상태를 만들어라.
   사례는 고령 대가야축제(경북/고령군/3월/테마3/인구3/접근성2).
   도면은 lib/preset.ts 의 presetLayout 을 그대로 쓴다.
   "시연용 예시"라는 표시를 화면에 남길 것 — 지어낸 데이터로 보이면 안 된다.

2. 빈 상태 네 가지를 눈으로 확인
   이력 0건 / TourAPI 키 없음 / 쌍둥이 0곳(강원 양구군·7월·테마7·인구0.5만·접근성1)
   / 도면 없음. 코드에는 다 있는데 실제로 다 본 적이 없다.

3. 진단서가 정말 A4 한 장인지 확인
   근거가 3종에서 5종 + 자기검증으로 늘었다. 인쇄 미리보기로 확인하고,
   넘치면 시기 표를 더 줄여라.

4. (내가 정하면) 자동 추출 모델 교체
   무료 모델 z-ai/glm-5.2:free 가 계속 429 를 뱉는다. 실패 문구와 직접 입력
   폴백은 이미 잘 되니 치명적이진 않다. 이건 나한테 물어보고 진행해.

작업 규약은 HANDOFF 의 "작업 규약" 절 그대로. 특히:
- 순수 함수 TDD → 화면 → npm test·typecheck·lint·build·test:e2e → 크롬 확인 → 커밋
- 화면 문구에 em-dash(—) 쓰지 마라. 한 문장에 strong 하나 이하.
- 크롬 자동화는 JS .click() 으로. 검증은 DOM 텍스트를 읽어서.

막히거나 판단이 필요하면 물어보지 말고 임의로 정한 뒤 docs/DECISIONS.md 에 근거를
남겨라. 단 push 는 검증 5단계가 전부 초록일 때만 한다.

1번부터 시작해.
```
