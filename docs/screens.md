# 화면 매핑 — 2026-08-29 (3차 멘토링 블록 01)

배포된 코드에서 뽑은 것이다. 기억으로 적지 않았다.
이 앱은 REST 라우트가 아니라 **한 페이지 + Server Action 3개**다. "엔드포인트"는 그 넷을 말한다.

## 엔드포인트 목록 (코드에서 뽑음)

| 메서드 | 경로/액션 | 요청에 필요한 것 | 응답에 오는 것 | 로그인 |
|---|---|---|---|---|
| GET | `/` (변형: `?manual=1` `?draft=<id>` `?q=<검색어>` `?err=<메시지>`) | 없음 | 화면 전체 — 입력부 + 진단 이력. `q` 가 있으면 TourAPI 검색 결과 목록 | 불필요 |
| POST | Server Action `추출` (붙여넣기 폼) | `planText` 20자 이상 8,000자 이하 | redirect `/?draft=<id>` — 실패 시 `/?err=…&manual=1` | 불필요 |
| POST | Server Action `선택` (검색 결과 폼) | `contentId`(숫자) · `title` · `addr1` | redirect `/?draft=<id>` — 실패 시 `/?err=…&manual=1` | 불필요 |
| POST | Server Action `저장` (확인·수정 폼) | `sido` `sigungu` `month` `theme` `population` `accessibility` | 이력 갱신된 `/` — 검증 실패 시 `/?err=…&manual=1` | 불필요 |

서버가 뒤에서 부르는 외부 API (화면이 직접 부르지 않는다): OpenRouter(기획서 추출) · TourAPI `searchKeyword2`/`detailIntro2`(축제 검색·개최일) · Neon Postgres(이력·초안).

## 플로우 3개

1. **축제 담당 공무원이** / 이미 쓴 기획서를 진단하려고 / 붙여넣기 → 확인·수정 → 진단 결과
2. **축제 담당 공무원이** / 기획서가 아직 없는 구상 단계에서 진단하려고 / 축제 검색(또는 직접 입력) → 확인·수정 → 진단 결과
3. **담당자·상급자가** / 지난 진단을 다시 보려고 / 첫 화면 → 이력에서 근거 펼치기

## 화면 목록 (플로우에 안 나오는 화면은 오늘 안 만든다)

| 화면 이름 | 사용자가 하는 일 | 부르는 엔드포인트 | 빈 상태 | 에러 상태 |
|---|---|---|---|---|
| 붙여넣기 ★ | 기획서 텍스트를 넣고 "기획서 읽어오기" | GET `/` → `추출` | placeholder 로 예시 기획서를 보여준다 | 짧은 입력·한도 소진·추출 실패 → 상단 배너 + 직접 입력으로 안내 |
| 축제 검색 결과 ★ | 이름으로 찾고 하나를 골라 초안 생성 | GET `/?q=` → `선택` | "○○ 로 등록된 축제를 찾지 못했습니다 — 직접 입력" | "검색에 실패했습니다 — 잠시 후 다시 / 직접 입력" |
| 확인·수정 ★ | 뽑힌 값을 근거와 대조해 고치고 "이 기획안 진단하기" | GET `/?draft=` `/?manual=1` → `저장` | 수동 입력이면 전 칸 빈 폼 + "문서에서 못 찾은 항목" 안내 | 검증 실패 항목을 한국어로 나열한 배너 |
| 진단 이력·결과 ★ | 경보 등급 확인, "왜 닮았나" 펼치기 | GET `/` (등급·매칭은 서버 렌더 계산) | "아직 진단한 기획안이 없습니다 …" | "이력을 불러오지 못했습니다. 저장은 남아 있습니다" |

★ = 오늘 진짜 데이터로 붙어 있는 화면 (4개 전부 — 검색은 실 TourAPI, 확인은 실 초안, 이력은 실 Postgres).
