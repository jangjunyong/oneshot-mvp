# 참고 사이트 — 레퍼런스 · 대체재

기록 2026-08-23. 아래 주소는 전부 직접 열어 확인했다.

## 레퍼런스

### DocsHunt — https://docshunt.ai/

> "모든 지원사업, 사업계획서를 작성하는 AI"

지원사업 공고별로 사업계획서를 자동 작성해 주는 플랫폼. 대상은 예비창업자·초기 스타트업.

**가져올 것**

- **3단계 골격이 우리와 같다.** 공고 선택 → AI 대화로 정보 입력 → 완성 문서 출력.
  우리는 기획안 입력 → 닮은 축제 탐색 → 등급 출력. 화면 수가 늘어날 때 이 구조를 넘지 않는다
- **양식과 평가 기준에 맞춰 생성한다** — 잘 쓴 글이 아니라 심사에 통과하는 글을 판다.
  우리가 파는 것도 정확도가 아니라 감사에서 댈 근거다. 같은 자리
- **랜딩에서 결과물을 먼저 보여준다.** 7페이지 사업계획서 샘플을 캐러셀로 깐다.
  우리 랜딩도 설명이 아니라 **경보 카드 실물**이 먼저 나와야 한다
- TAM/SAM/SOM·경쟁사 비교표 같은 시각 자료를 곁들여 근거처럼 보이게 만든다 —
  우리의 "왜 닮았나(축별)" 패널이 같은 역할이다

**가져오지 않을 것**

- AI 채팅으로 정보를 받는 입력 방식. 우리는 폼 + **되물음 1회** ([`FLOW.md`](FLOW.md))
- 사용할수록 쌓이는 메모리 — 상태를 만들지 않는다

### 한국관광 데이터랩 — https://datalab.visitkorea.or.kr/datalab/portal/main/getMainForm.do

한국관광공사 공식 관광 빅데이터 포털. **데이터 출처이자 가장 큰 대체재.**

메뉴 6개 — 지역별 분석 · 국가별 분석 · 관광산업 분석 · **테마별 분석** · 빅데이터(이동통신/신용카드/내비게이션) · 관광통계/실태조사.

**테마별 분석 > 축제현황** 아래에 두 개가 있다.

| 메뉴 | 하는 일 |
|---|---|
| 문화관광축제 현황 | 지정 축제 목록·현황 |
| **행사/축제 DIY 맞춤 분석** | 개별 행사·축제 **성과분석** |

**선 긋기 —** DIY 맞춤 분석은 **이미 열린 축제의 성과를 사후에** 센다.
우리는 **아직 열리지 않은 기획안**을 받는다. 이 시점 차이가 유일한 차별점이므로
데모 첫 화면이 "입력 폼"이 아니면 데이터랩 하위호환으로 읽힌다.

화면은 탭 기반 대시보드 + 지도 시각화, "전월 대비 / 전년 동기 대비" 비교지표. 무겁다.
우리는 한 화면에서 끝낸다.

## 여기서 나온 세 문장

멘토가 "데이터랩에 있지 않나요"라고 물으면 이걸로 답한다.

> 데이터랩은 **끝난 축제**를 분석합니다. 저는 **예산 집행 전 기획안**을 받습니다.
> KT는 **몇 명 온다**를 말합니다. 저는 **닮은 축제 3곳이 평소의 2.4~3.1배였다**를 말합니다.
> 인파관리시스템은 **사고가 시작된 뒤** 켜집니다. 저는 **넉 달 전** 켜집니다.

셋 다 시점으로 갈랐다. 선행 사례를 부정하지 않고 자리를 좁히는 방식이다.

## 기획서 양식은 통일돼 있는가 — 확인 결과

**결론: 표지 한 장만 통일돼 있고, 알맹이는 안 통일돼 있다.**

「재난 및 안전관리 기본법 시행규칙」 **[별지 제20호의3서식] 지역축제 안전관리계획서**
(2024. 3. 26. 개정) — 법정 서식이 실제로 존재한다. 전문을 받아 칸을 확인했다.

- 서식 목록 — https://www.law.go.kr/LSW/lsBylInfoPLinkR.do?lsiSeq=272675&bylNo=0020&bylBrNo=03&bylCls=BF
- 서식 원본(PDF) — https://www.law.go.kr/LSW/flDownload.do?gubun=&flSeq=161371083&bylClsCd=110202
- 근거 조문 — 법 제66조의11제3항 · 시행령 제73조의9제6항 · 시행규칙 제19조의4

| 칸 | 내용 |
|---|---|
| 제출자 | 성명(기관명) · 생년월일 · 주소 · 전화번호 |
| 지역축제 명칭 | |
| 기간 | |
| 개최장소 | |
| 주최 | 주최기관(대표자) · 주소 · 전화번호 |
| **주요내용** | **자유 서술** — ※ 공연, 위험물질 사용(폭죽·불꽃·인화성 물질) 여부 표기 |
| **첨부서류** | **지역축제 안전관리계획** |

**법이 통일한 것은 봉투다.** 실제 계획서는 "첨부서류: 지역축제 안전관리계획" 한 줄로
빠져 있고, 그 첨부가 지자체마다 다른 문서다. 그래서 자유 텍스트 추출이 필요하다.

그리고 이 서식은 **축제가 확정된 뒤** 시장·군수·구청장에게 내는 문서다.
우리가 노리는 **예산 집행 전 기획 단계**에는 법정 서식이 아예 없다.

### 우리 5축과 대조

| 축 | 표지에서 나오나 |
|---|---|
| 지역 | ✅ 개최장소 |
| 시기 | ✅ 기간 |
| 테마 | ❌ 「주요내용」 자유 서술에서 읽어야 함 |
| 접근성 | ❌ 본문에서 판단해야 함 |
| 인구 | ❌ (지역이 정해지면 주민등록인구로 채움) |

표지만으로는 2축이다. 나머지는 문서를 읽어야 한다.

### 발표에 쓸 카드

**이 법정 서식에는 「예상 참가인원」 칸이 없다.**
국가가 만든 서식조차 그 숫자를 묻지 않는다 — PRD 의 *"예상 방문객 수 입력란을
만들지 않는다"* 를 법정 서식이 뒷받침한다.

### 양식이 통일되면 어떻게 되나

행안부·문체부가 고시하면 가능하지만 그건 정책이다. 그리고 통일될수록
추출이 쉬워진다 — **위협이 아니라 순풍이다.**
