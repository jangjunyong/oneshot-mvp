# 기능 1: 사용자가 축제 조건을 넣으면 닮은 과거 축제 3개를 볼 수 있다

배포: https://oneshot-mvp.vercel.app

## 완료 조건

- [ ] 저장을 누르면 그 줄 아래에 과거 축제 이름 세 개가 보인다
- [ ] 축제마다 개최 연도와 평소 대비 배수(`N.NN배`)가 같이 보인다
- [ ] 축제마다 무엇이 닮았는지 항목 이름이 보인다 (지역·시기·테마·인구·접근성 중)
- [ ] 서울 강남구 · 2월 · 음악 · 인구 119만 · 접근성 5 를 넣으면 **"비교할 만한 과거 축제가 없습니다"** 와 찾아본 범위가 보인다
- [ ] 같은 값을 두 번 저장하면 두 줄의 축제 이름과 순서가 같다

## 안 되는 경우

- **시군구가 데이터에 없을 때** → 지역 축을 빼고 나머지 네 축으로만 잰다. 좌표를 지어내지 않는다
- **인구나 접근성이 숫자가 아닐 때** → 저장 버튼이 안 눌린다
- **닮은 축제가 한 곳도 임계값 안에 없을 때** → 억지로 가장 가까운 걸 내놓지 않고 "비교할 만한 과거 축제가 없습니다" + 찾아본 범위

## 이번에 안 하는 것

- 경보 등급과 한 문장 (기능 2)
- "왜 닮았나" 접기·펼치기 (기능 3)
- 기획안 텍스트 LLM 파싱
- 디자인·레이아웃 정리

## 건드릴 파일

새로 만들 것 — `lib/festivals.ts` (데이터 로드) · `lib/match.ts` (거리 계산) · `lib/match.test.ts`
고칠 것 — `app/page.tsx` (목록에 결과 붙이기) · `lib/store.ts` (결과를 같이 저장할지는 아래 참조)

## 확인 방법

`npm test` → `npm run typecheck` → 배포 URL 에서 김천 조건과 극단 조건 두 개를 직접 눌러본다.

## 물어볼 것

**1. 저장소 — 이게 제일 급합니다.**
스켈레톤은 서버 메모리에 쌓는데 **배포본에서 안 남습니다.** Vercel 서버리스가 요청마다 다른 인스턴스를 띄워서, 저장한 인스턴스와 목록을 읽는 인스턴스가 다릅니다. 로컬은 통과하고 배포본은 확인 절차 3·4번이 실패합니다.
→ Vercel Postgres 를 만들고 `@vercel/postgres` 를 설치할지, 아니면 저장을 빼고 조회 결과만 보여줄지.

**2. 테마를 어떻게 입력받을지.**
데이터의 `themeCode` 는 1~8 숫자인데 **원본 분류표를 아직 못 구했습니다.** 지금 폼은 자유 텍스트(`음식`)라 데이터와 맞출 수가 없습니다.
→ 표본에서 읽어낸 임시 이름으로 드롭다운 8개를 만들지, 숫자를 그대로 받을지.

**3. 시군구·인구·접근성 입력 방식.**
지금은 셋 다 자유 입력입니다. 시군구에 오타가 나면 지역 축이 통째로 빠지고, 인구·접근성은 지역만 고르면 데이터에서 자동으로 채울 수 있습니다.
→ 시도·시군구를 드롭다운으로 바꾸고 인구·접근성을 자동으로 채울지.

## PLAN.md 와 달라진 것

**결과를 보여줄 화면이 없습니다.** PLAN 의 완료 조건은 별도 결과 화면을 가정했는데, 스켈레톤은 입력·목록이 `app/page.tsx` **한 페이지**에 있고 Server Action 이 같은 페이지를 다시 그립니다. 결과를 목록 항목 아래에 붙이면 화면을 새로 만들지 않아도 됩니다 — 그렇게 할지 정해 주세요.
