## 절대 어기지 않는 것 (제품 불문율)

1. **방문객 수를 예측하지 않는다.** 화면 숫자는 과거가 실제로 겪은 *평소 대비 배수*뿐이다.
2. **"안전하다"고 말하지 않는다.** 근거를 못 찾은 것과 안전한 것은 다르다.
3. **왜 닮았는지를 항상 같이 낸다.** 유사도 점수만 던지면 실무자는 못 믿는다.
4. **출처 없는 숫자·그림을 화면에 올리지 않는다.** 못 구한 값은 비우고 "못 구했다"고 적는다.
5. **판정·시뮬에 LLM 0회.** 모델은 기획서에서 항목을 옮겨 적는 1회만.

`evals/cases.md` 09행이 4번의 판정 기준이다. **2026-08-31 에 판정 문장을 고쳤다** —
옛 문장("화면의 숫자가 전부 입력값·지역 인구·실측 배수·연도 중 하나인가")은 화면을 못
덮어 **한 번도 통과한 적이 없었다**(부하 지수·부지 면적·적중률·또래 순위가 다 그 네
범주 밖이고, 어느 것도 방문객 수 예측이 아니다). 지금 판정은 둘이다.

1. 화면의 숫자가 입력·실측·실측에서 센 값·도면에서 잰 값으로 **되짚어지는가**
2. **사람 수(명)와 금액(원)이 붙은 숫자가 0건인가** ← `e2e.test.mjs` 가 매번 잰다

기대는 안 바뀌었다("방문객 수 예측값을 출력하지 않는다"). 자의 눈금만 고쳤다.

  ```js

     pr+=[...r.cssRules].map(x=>x.cssText.replace(/;/g,' !important;')).join('\n');}
  const st=document.createElement('style');
  st.textContent='body{margin:0}\n.no-print{display:none!important}\n.report{width:186mm!important}\n'+pr;
  document.head.appendChild(st);
  // 가용 273mm 와 견준다
  document.querySelector('.report').getBoundingClientRect().height/(96/25.4)
  ```
  최악을 보려면 경쟁 목록 `li` 를 상한까지 복제하고 축제명을 한 줄 더 흐르게 늘린다.

빌드 id·액션 해시·시각처럼 매번 바뀌는 값만 자리표시자로 바꾸고 **나머지는
바이트로 비교**한다. 액션 해시는 지우지 않고 자리표시자로 바꾸므로 개수와
등장 순서는 계속 비교된다 — e2e 가 기대는 "첫 액션이 추출 폼"이 그대로 지켜진다.

이 그물이 무는지도 확인해 두었다. 문구 한 단어를 바꾸면 `home-*` 6개만
걸리고 `venue`·`report` 는 그대로다. 처음에는 **모든 화면이 항상 다르다**고
나왔는데 원인이 Next 의 빌드 id 였다 — 정규화에 넣었다.

AI 티가 난다는 지적을 받고 걷어냈다. 새로 문구를 쓸 때 같은 함정을 피할 것.
- **em-dash(—) 남용 금지.** 끊어 쓴다.
- **한 문장에 `<strong>` 하나 이하.** 다 강조하면 아무것도 안 강조된다.
- 괄호 설명 겹치지 않기. 나열(A · B · C)을 문장으로 편다.
