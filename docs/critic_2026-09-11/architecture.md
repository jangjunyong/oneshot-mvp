# 1부. 이 웹서비스가 어떻게 굴러가는가

## 0. 한 문장 비유

**학교 축제 준비위원장이 "올해 3천 명 올 거예요" 하고 예산을 타러 왔다.**

선생님이 물어야 할 건 "3천 명 맞아?"가 아니다. 그건 아무도 모른다.
선생님이 물을 수 있는 건 이거다.

> "작년 이 학교 축제날에 **정문을 통과한 사람이 실제로 몇 명이었지?**
> 평소 등교 인원의 **몇 배**였지?
> 네가 말한 3천 명은 그 배수의 **몇 배**를 요구하는 숫자지?"

이 서비스가 딱 그걸 한다. 다만 학교가 아니라 **시군구**고, 정문 카운터가 아니라
**KT 휴대폰 기지국이 센 시군구 일별 체류 인구**(한국관광공사가 공개한 것)다.

그래서 이 서비스는 **"몇 명 온다"를 절대 말하지 않는다.**
말하는 건 셋뿐이다 — **판정**(통과/주의/과대/...), **몇 배**, **구간**.

## 1. 화면 6개 — 담당자가 지나가는 순서대로

나침반(상단 메뉴)은 네 화면에서 똑같은 순서로 고정돼 있다.
`/check → /evidence → /venue → /(진단, 보조)` — `lib/copy.test.ts:92-100` 이 이 순서를 기계로 지킨다.

### ① `/check` — 기획안 판정 (주인공)

파일: `app/check/page.tsx` (542줄)

담당자가 폼에 여섯 가지를 적는다.

| 칸 | 예 (군포 견본) |

| 축제 이름 | 군포철쭉축제 |
| 시도 · 시군구 | 경기 · 군포시 |
| 예상 방문객 | 600,000명 |
| 이 숫자의 단위 | **기간 총계** × **연인원** (라디오 4개, 둘 다 골라야 판정이 돈다) |
| 총예산 | 100,000만 원 (= 10억) |
| 기획 기간 · 지난 회차 기간 3칸 | 2027-04-17~25 / 2024·2025·2026 각 9일 |

누르면 **SECTION B**에 3단 판정표, 내년 배수 구간 카드, 1인당 예산 카드,

아무것도 안 적고 들어오면 **군포 견본**이 자동으로 선다 (`lib/checkquery.ts:126-131`).
심사위원이 시크릿 창으로 열어도 첫 화면이 비지 않게 하려는 것.
`?demo=hwacheon` 을 붙이면 화천산천어축제 견본(186만 → 상한 초과)으로 바뀐다.

## 3. 판정 엔진 3단계 — 군포 60만으로 풀어 보기

엔진은 `lib/verdict.ts` 의 `checkVisitors()` 하나다 (`:140-431`). 순수 함수 — API·DB·시각을 모른다.

**입력**: 예상 방문객 600,000명 · 기간 총계 · 연인원
**실측**: 군포시(코드 41410) 2026 축제 기간 2026-04-18~26 (9일)

### 1단계 — 모집단 상한 (하드 게이트)

> "그 기간에 **군포시에 있던 모든 사람**(현지인+외지인+외국인) 연인원이 얼마였나?"

```
                    기획안 600,000명
  상한비 =  ────────────────────────────────  =  0.28
            2026 기간 전체 체류 연인원 2,147,879명
```

임계: **≥0.80 상한 초과 · 0.50~0.79 과대 · <0.50 통과** (`lib/verdict.ts:73`)
→ **0.28 이므로 통과.** 화면 문장: "…이므로 이 값은 그중 **28%**이다."

> 참고 — 화천 견본은 여기서 걸린다. 186만 ÷ (화천군 기간 체류) = **2.34** → 상한 초과.
> 이때만 **손익분기 회전율** = N ÷ (0.80 × 상한) = **2.93회**를 같이 낸다 (`lib/verdict.ts:195-196`).
> "불가"라고 안 하고 "한 사람이 평균 2.93번 잡혀야 이 숫자가 선다"라고 말한다.
> 회전율 값 자체는 **가정하지 않는다** — 그 근거는 담당자가 댄다.

### 2단계 — 순증분 (보조 신호)

> "축제가 **실제로 끌어온** 사람이 몇이었나?" (같은 요일 중앙값 대비 증가분의 합)

```
                     600,000명
  증분비 =  ─────────────────────────────  =  4.6
            2026 축제가 끌어온 연인원 130,350명
```

임계: 기간 총계는 **≥3.0 이면 주의 신호** (`lib/verdict.ts:74`)
→ **4.6 ≥ 3.0 → 주의 신호.** 단독으로는 판정을 못 내리고, 3단계 결과를 한 칸 올리는 데만 쓴다.

### 3단계 — 동일 정의 배수 (주 근거)

> "기획안은 **평소의 몇 배**를 요구하나? 이 축제가 실제로 겪어 본 배수는 몇 배였나?"

```
  요구 배수 =        600,000명            =  0.91배
              ──────────────────────────
              평소 외지인 중앙값 × 9일
              = 658,382명

  이력 최대 평균 배수 = max(1.21, 1.16, 1.21) = 1.21배   ← 2024·2025·2026

            0.91
  r  =  ────────  =  0.76
            1.21
```

임계: **r<0.70 과소 · ≤1.00 통과 · ≤1.30 주의 · >1.30 과대** (`lib/verdict.ts:75`)
→ **0.76 이므로 통과.**

### 최종 집계 (`lib/verdict.ts:393-400`)

```
1단계 상한 초과?  아니오
        ↓
3단계 결과       통과
        ↓
2단계 주의 신호?  예  →  통과를 한 칸 올린다
        ↓
      최종 판정   주의
```

**군포 60만 = 주의.** 화면 맨 위에 "예상 방문객 **주의**" 가 뜨고,
보완 문장이 "이력 상한을 기준으로 물량을 잡되 넘는 몫은 예비로 두고,
축제가 실제로 끌어온 순증(비 4.6)을 예산 심의에 같이 낸다"라고 다음 행동을 준다.

> **모든 임계값은 "정한 값"이다.** 군포 2025 한 건으로 맞췄고, 화면이 그 사실을 그대로 적는다
> (`app/check/page.tsx:348-353`). 다도시 재현은 아직 없다.

## 4. 낱말 여섯 개 — 쉬운 말로

### 619건
한국관광 데이터랩 웹에서 정적으로 긁어 온 전국 축제 619건 목록이다(`data/festivals.json`).
원래 붙어 있던 배수는 산출식이 코드에 안 남아 있어서, **2026-09-09 에 전부 다시 쟀다**
(`scripts/recompute619.ts` → `data/festivals.surge.json`, 619/619 성공).
그래서 지금은 `/check` 의 자기 이력과 `/` 의 닮은 축제가 **같은 자로 잰 배수**다
(`lib/festivals.ts:23-26`). 619건은 **보조 근거**다 — 화면이 먼저 그렇게 말한다.

### 배수
**축제일 외지인 ÷ 평소 외지인.** "평소"는 축제 전후 각 4주(축제일 제외) 외지인의 **중앙값**이다
(`lib/surge.ts:163`). 평균이 아니라 중앙값을 쓰는 건 연휴 같은 이상치에 끌려가지 않기 위해서.
평균 배수(`multMean`)와 최대일 배수(`multPeak`) 둘을 낸다 (`lib/surge.ts:229-230`).
**이 파일이 제품의 유일한 배수 정의다** — 배수를 계산하는 코드를 여기 말고 두지 않는다.

### 순증
배수와 분모가 다르다. 순증은 **같은 요일끼리** 비교한다 (`lib/surge.ts:166-172`).
토요일 축제일의 외지인에서 "평소 토요일" 외지인 중앙값을 뺀 값이다.
"토요일이라 원래 많다"를 걷어내야 "축제가 끌어온 몫"이 남기 때문.
기간 전체로 더한 것이 `visitors` = Σ(ΔV + max(0, ΔL)) — 축제가 끌어온 연인원.

### 내년 구간
**예측이 아니라 이력의 연장이다** (`lib/range.ts:1-10`).
연도별 배수의 최소~최대를 0.1 단위로 **바깥 반올림**한다 — 구간은 값을 감싸야지 잘라내면 안 된다.
군포: 평균 (1.16, 1.20, 1.21) → **1.1~1.3배**, 최대일 (1.47, 1.52, 1.52) → **1.4~1.6배**.
2026-09-10 에 "신뢰도 높음" 라벨을 **폐기했다** — 재지 않은 것에 신뢰도를 붙이는 건 출처 없는 숫자라서.

### 또래
같은 **인구 구간**의 619건 축제들 배수 분포에서 **중앙값~상위 5%** 를 꺼낸 것 (`lib/peerband.ts`).
군포는 "인구 12~30만 지역 축제 **168곳**", 평균 1.2~1.8배 · 최대일 1.3~2.4배.
자기 이력이 없거나 1년뿐일 때 3단계의 비교 대상이 되고, 내년 구간 카드의 둘째 줄이 된다.

### 백테스트 (−52주 근사)
"이 구간이 다음 해를 맞히긴 하나?"를 재려면 **같은 축제의 다년 표본**이 있어야 하는데 그게 **0건**이다
(619건은 축제당 1행, TourAPI 는 과거 연도를 안 남긴다. 군포 3개년만 예외).
그래서 각 축제 기간을 **−364일·−728일** 옮긴 창을 "근사 전 회차"로 삼았다 (`lib/backtest.ts:1-17`).
364 = 52주라 요일이 맞는다.

결과: 표본 381건. 두 해 채택(n=2) **325건 중 167건 = 51.4%**, 한 해+또래(n=1) 56건 중 31건 = 55.4%.
**절반이다.** 그리고 편향이 양방향이다 — 채택 필터(최대일 배수 ≥1.3)가 안정적인 대형 축제만 남겨
적중률을 올리고, −52주 근사 자체가 실제 기간과 어긋나 적중률을 내린다. 어느 쪽이 큰지는 재지 않았다.
이 세 요소(근사·표본 N·편향 양방향)를 전부 담은 문장을 `backtestSentence()` **하나**가 만들고,
두 화면이 같은 함수를 부른다 (`lib/backtest.ts:246-255`) — 어긋날 수가 없다.

### 워커가 돌려보내는 것 (`app/venue/sim-protocol.ts`)

| 메시지 | 빈도 | 내용 |
|---|---|---|
| `built` | build 1회 | 격자 크기·보행가능 면적 |
| `frame` | **50ms 마다** | 좌표 `Float32Array(n*2)` + 상태 `Uint8Array(n)`. **transfer** 로 복사 없이 넘긴다. 밀도는 **5프레임(250ms)마다만** 동봉 |
| `summary` | 500ms 마다 | 최대 밀도·병목 목록·대기열 |
| `headlessDone` / `stressDone` | 작업 끝 1회 | 질문·스트레스 결과 |

사람 이름 붙이기(`nearestName`)는 **메인이 한다** — 워커는 좌표만 보낸다.

### 엔진 — CFSM

`lib/sim/sim.js`. **Collision-Free Speed Model** (Tordeux·Chraibi·Seyfried 2015).
사회력 모델이 아니라, **앞사람과의 간격이 내 속도를 정하는** 1차 모델이다. `dt = 0.1초`.

- **방향**: 목적지마다 격자 다익스트라로 **flow field**(거리장)를 한 장씩 미리 만들고, 사람은 내리막을 따라간다 (`sim.js:100, 139-170`).
- **격자**: 0.5m. 셀이 30만 개를 넘으면 자동으로 1.5m 까지 키운다 (`sim.js:206, 221-223`). 밀도 격자는 따로 2m.
- **결정론**: `mulberry32(seed)` — 같은 씨앗이면 같은 결과 (`sim.js:214`).
- **검증**: Weidmann 기본도표 ±30% 안(7점 중 6점, 전부 느린 쪽 = 밀도 과대·상한 배수 과소). 그 스크립트는 **저장소 밖**(`시뮬_데모/`)에 있다.

### `personsPerAgent (k)` — 점 하나가 몇 명인가

`sim.js:227`. 기본 1명. 질문 재생은 5명/점으로 강제(`sim-map.tsx:913`), 스트레스는 1명 강제(`sim.worker.ts:121`).
**k > 1 이면 줄·서비스 자리 기하가 k 를 안 따라가 밀도가 부푼다** — 같은 도면에서 3명/점은 7.22, 1명/점은 2.00 이 나왔다(`sim-map.tsx:432-434`). 화면이 그 경고를 적는다.

### 밀도 등급 (`lib/sim/sim.js:16-27`)

```
여유 <1.0  보통 <2.0  혼잡 <3.0  주의 <4.0  경계 <5.0  위험 ≥5.0   (명/㎡)
             WATCH_DENSITY = 3.0                LIMIT_DENSITY = 5.0
```

경계 3·5명/㎡ 는 **행정안전부 「다중운집인파사고 안전관리 가이드라인」(2024.9)** 의 값이다
(근거 주석 `sim.js:12-15`). 셀마다 3 이상·5 이상으로 **몇 초 있었는지**를 누적한다 (`sim.js:490-491`).

### 스트레스 테스트

`sim.worker.ts:116-133`. 유입 배수를 **0.5씩 올리며** 1.5시간짜리를 다시 돌리고,
**위험(5명/㎡)이 60초를 넘게 유지되는 첫 배수**에서 멈춘다 (`:130`).
"몇 배까지 감당되는가"의 답이 그 배수다.

### 질문 → 시나리오 → 시뮬

담당자가 "17번 부스에 사람 몰리면 어떻게 돼요?" 라고 한글로 묻는다.
LLM(`gemini-2.5-flash-lite`)이 그 말을 **시나리오 JSON 으로 번역만** 한다 — 답은 안 한다.
번호 지목("17번")은 **규칙이 모델을 이긴다** (`lib/simask.ts:147-152`).
그다음 워커가 60분 헤드리스로 돌리고, **숫자는 전부 시뮬의 `summary()` 에서만** 나온다.
키가 없거나 하루 60건을 넘으면 규칙 폴백 (`app/venue/ask-action.ts:11-31`).

클라이언트 컴포넌트는 **도면 시뮬과 3D 지도 둘뿐**이다.

### "상태가 URL 에 있다"는 게 무슨 뜻인가

`/check`·`/evidence`·`/report/check` 는 **저장소를 쓰지 않는다.** 입력이 전부 쿼리 문자열이다.

```
/check?sido=경기&sigungu=군포시&n=600000&basis=period&counting=personDays
      &budget=100000&start=2027-04-17&end=2027-04-25&h1s=2024-04-20&…
```

이게 왜 중요한가:

1. **같은 링크면 같은 판정.** 심사위원이 링크를 복사해 다른 컴퓨터에서 열어도 화면이 똑같다.
   판정 엔진이 순수 함수라 난수·시각·세션이 끼어들 자리가 없다.
2. **자바스크립트가 죽어도 산다.** GET 폼이라 브라우저가 알아서 제출한다.
3. **테스트가 브라우저를 흉내낼 수 있다.** e2e 15건이 그래서 가능하다.
4. **로그인이 필요 없다.** 상태가 서버에 없으니 사용자를 구분할 이유가 없다.
   (2부에서 보겠지만, 이게 쿼터 문제의 원인이기도 하다.)

`/` 와 `/venue` 만 저장이 있다 — Neon Postgres 3테이블(`entries`, `venues`, `drafts`).

## I. 검토자 주석 — 이 검토가 말하지 않는 것

- **실행 검증을 하지 않았다.** `npm test`·`npm run build` 를 돌리지 않았고,
  브라우저로 `/venue` 를 조작하지도 않았다. #1(질문 영구 잠김)은 **코드 경로 추적으로 확정**했으나
  실제 재현은 안 했다. 고치기 전에 한 번 재현해 보길 권한다
  (도면 편집 모드에서 게이트 4개를 전부 끄고 질문 → 그다음 질문이 되는지).

  나는 그 스크립트를 못 봤다. 시뮬 수치의 타당성은 이 검토의 범위 밖이다.

  통계적으로 타당한지는 도메인 질문이다. 코드는 그게 "정한 값"이고 "군포 2025 한 건으로 맞췄다"는 것을
  화면에 그대로 적고 있다 — **적어도 숨기지는 않는다.**
