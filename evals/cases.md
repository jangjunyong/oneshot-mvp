# evals — 믿을 근거 열 줄

> 강의 p29~30: LLM 앱은 단위 테스트로 안 잡힌다. 필요한 건 프레임워크가 아니라 **표 한 장**이다.
> 이 표가 그대로 작업 지시의 **"완료 조건"** 이 되고, 그게 **에이전트의 눈**이 된다.

이 제품은 **원인을 진단**한다. 그래서 대부분의 케이스는 *"그래프가 그려지는가"* 가 아니라 **"올바른 원인을 짚는가"** 를 잰다.
실패해야 정상인 케이스가 **5개(06~10)**. 강의 요구는 3개 이상이다.

## 진단이 갈리는 케이스 — 가설별 정답

| # | 입력 | 기대 원인 | 판정 |
|---|---|---|---|
| 01 ★ | 다우데이타 · 다우기술 · 키움증권 | **가설1 지배구조** — "한 덩어리" | 주 원인 == 지배구조 · 덩어리 1개 |
| 02 | 현대차 · 기아 | **가설1** — 현대모비스 경유 | 다리 놓는 회사에 현대모비스가 있는가 |
| 03 ★★ | 삼성전자 · 강원랜드 (지배구조 무관, 둘 다 국민연금 5%↑) | **가설2 공동 대주주** — "분산은 맞는데 같은 자금" | **"계열 때문"이라고 답하지 않는가** · 🟣 문장이 나오는가 |
| 04 ★★ | 지배구조·대주주·업종 전부 무관한 3종목 | **가설4 시장 전체** — "분산 문제가 아닙니다" | **억지로 계열을 만들지 않는가** (암묵지 2번) |
| 05 | SK하이닉스 · DB하이텍 | **가설3 같은 업종** | 업종을 원인으로 짚되 **덩어리 판정에는 안 넣는가** |
| 06 | 01의 결과에서 "근거 보기" | 그래프가 펼쳐지고, 관계 클릭 시 보고서·연도·항목 | 기본은 **접혀** 있는가 · 세 값이 비어 있지 않은가 |

## 실패해야 정상

| # | 입력 | 기대 | 판정 |
|---|---|---|---|
| 07 ★ | 증거가 약한 조합 | **"~일 수 있습니다"** 로 낮춰 말한다 | 약한 증거를 단정하지 않는가 |
| 08 ★ | 코스피200 밖 종목 | 온디맨드 시도 후, 없으면 안내 | **500이 아닌가** |
| 09 ★ | 없는 종목명 ("삼성전자우우우") | 되물음 | 에러 없이 처리되는가 |
| 10 ★ | 1종목만 입력 | "관계는 2종목부터" 안내 | 빈 화면으로 끝나지 않는가 |
| 11 ★ | DART 응답 실패 (키 제거로 재현) | **그 가설만 "확인 못 함"**, 나머지로 답한다 | 전체가 멈추지 않는가 · 재시도 1회 후 중단하는가 |

## 함정 방어

이 넷이 빠지면 제품이 조용히 무의미해진다.

| # | 확인할 것 | 판정 |
|---|---|---|
| **12 ★★** | 🟣 공동 대주주를 그래프 간선으로 쓰지 않는가 | 국민연금을 거쳐 전체가 이어지지 않는가. **지우지도, 간선으로 쓰지도 말 것** |
| **13 ★★** | **가설 4를 항상 확인하는가** | 시세 소스가 없는 슬라이스 1~3에서는 *"시장 전체는 아직 확인하지 않습니다"* 라고 **명시**하는가. 조용히 빠뜨리면 실패 |
| 14 | 배경 회색 노드 클릭·호버·확대 | 아무 일도 안 일어나는가 (중장년층 오조작 방지) |
| 15 | 같은 입력을 두 번 | **같은 진단**이 나오는가 (LLM과 갈리는 지점) |

**13번이 제일 중요하다.** 시세를 못 붙였다는 이유로 가설 4를 조용히 건너뛰면, 이 제품은 **무조건 "계열 때문"이라고 답하는 도구**가 된다. 그게 암묵지 2번이 막으려는 실패다.

## 별도로 재는 것

| 항목 | 기준 |
|---|---|
| **에이전트/워크플로우 재판정** | 입력마다 **가설 1의 조회 깊이가 달라지는가.** 항상 같으면 워크플로우로 전환 (`docs/FLOW.md` §1) |
| 주주 문자열 → `corp_code` 매칭 | 정답 라벨 20~30건 대비 정밀도. Day 3에 라벨 작성 |
| 최대 스텝 | 8스텝 초과가 발생하지 않는가 |
| 응답 지연 | 첫 가설 로그까지 3초 이내 |

## 정답 라벨 — 전부 미검증

01·02·03·04의 기대값은 **실제 데이터로 확인한 값이 아니다.** 후보 출처는 [`docs/대체재_검증.md`](../docs/대체재_검증.md)의 Gemini 답변이고, **그 답변에는 명백한 오류가 섞여 있었다.**

| 후보 | 상태 |
|---|---|
| 다우데이타 · 다우기술 · 키움증권 | 🔲 Day 3 확인 |
| 현대차 · 기아 · 현대모비스 | 🔲 Day 3 확인 |
| 영원무역 · 영원무역홀딩스 | 🔲 Day 3 확인 |
| 동원산업 · 동원시스템즈 | 🔲 Day 3 확인 |
| **04용 "전부 무관한 3종목"** | 🔲 Day 3 확인 — 3홉 안에 정말 안 이어지는지. 이어지면 교체 |

> **추측으로 적은 기대값은 eval이 아니라 또 하나의 암묵지다.**
> DART로 실제 관계가 잡히는지 확인한 뒤에만 정답 라벨로 승격한다. — 이 문서가 LLM에게 지적한 바로 그 잣대를 이 표에도 적용한다.

## 쓰는 법

1. 필요한 줄을 골라 작업 지시의 `## 완료 조건`에 그대로 붙인다
2. 에이전트가 읽고 스스로 돌려본 뒤 스스로 고친다
3. 통과하면 커밋. 커밋 하나 = 지시 하나 = 되돌리기 지점 하나

지금은 손으로 돌린다. 자동화는 케이스가 20개를 넘을 때 생각한다 — *"평가 프레임워크를 고르다 이틀을 쓰는 팀이 매번 나옵니다."*
