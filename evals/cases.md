# evals — 믿을 근거 열 줄

> 강의 p29~30: LLM 앱은 단위 테스트로 안 잡힌다. 필요한 건 프레임워크가 아니라 **표 한 장**이다.
> 이 표가 그대로 작업 지시의 **"완료 조건"** 이 되고, 그게 **에이전트의 눈**이 된다.

실패해야 정상인 케이스가 **5개(07~11)**. 강의 요구는 3개 이상이다.

## 본 표

| # | 입력 | 기대 | 판정 |
|---|---|---|---|
| 01 ★ | 김천김밥축제 1회 조건 (인구·시기·테마·규모) | 닮은 축제 3개가 나온다 | 결과 개수 == 3 · 거리 임계값 이내인가 |
| 02 | 01의 결과 | **무엇이 닮았는지 항목별로** 보인다 | 지역·시기·테마·규모 중 닮은 항목이 표시되는가 (암묵지 2번) |
| 03 ★ | 01의 결과 | 경보 등급과 **한 문장**이 맨 위에 뜬다 | 등급이 나오는가 · 문장이 그래프·표보다 앞 DOM 순서인가 |
| 04 | 03의 등급 | 근거가 된 과거 축제의 **평소 대비 방문 배수**와 개최 연도가 있다 | 두 값이 모두 비어 있지 않은가 |
| 05 | "왜 닮았나" · "그들이 겪은 것" | 기본은 **접혀** 있고, 눌러야 펼쳐진다 | 초기 렌더에서 숨겨져 있는가 |
| 06 | 근거 항목 클릭 | 출처와 연도가 보인다 | 출처 없는 숫자가 화면에 없는가 |

## 실패해야 정상

| # | 입력 | 기대 | 판정 |
|---|---|---|---|
| **07 ★★** | 위험 근거가 약한 기획안 | **"안전합니다"라고 말하지 않는다.** "판단 못 함" | 안전 판정 문구가 0건인가 (암묵지 3번) |
| **08 ★★** | 아무것과도 안 닮은 조건 (예: 극단적 규모) | **"비교할 만한 과거 축제가 없습니다"** + 찾아본 범위 | **억지로 가장 가까운 걸 내놓지 않는가.** 임계값이 작동하는가 |
| 09 ★ | 닮았는데 결과 기록이 없는 축제 | "결과 미기록"으로 따로 표시하고 **등급 계산에서 제외** | 빈칸을 채워 넣지 않는가 |
| 10 ★ | 필수 항목이 빠진 기획안 텍스트 | 무엇이 없는지 짚어 되묻는다 | 에러 없이 처리되는가 |
| 11 ★ | 외부 API 응답 실패 (키 제거로 재현) | 정적 데이터만으로 축소 응답 + 배지 | 전체가 멈추지 않는가 · 재시도 1회 후 중단하는가 |

## 함정 방어

| # | 확인할 것 | 판정 |
|---|---|---|
| **12 ★★** | **방문객 수 예측값을 출력하지 않는가** | 화면 어디에도 "○○명 예상" 형태의 생성된 숫자가 없는가. **이 제품의 존재 이유다** |
| 13 | 서로 다른 입력 10개를 넣었을 때 | 늘 같은 축제 3개만 나오지 않는가 (특징 편중) |
| 14 | 같은 입력을 두 번 | **같은 결과**가 나오는가 |
| 15 | 경보 등급을 흑백으로 보면 | 색 없이도 등급이 구분되는가 (색각 고려) |

**12번이 제일 중요하다.** 어느 슬라이스에서든 "몇 명 올 것 같다"를 출력하기 시작하면, 이 제품은 틀릴 수 있는 예측기가 되고 한 번 틀리면 아무도 안 쓴다.

## 정답 라벨 — 미검증

**방문 배수(`actualVisitSurge`)는 619건 전부 실측값이다.** 반면 01·08의 "닮은 축제 3개"가 무엇일지는 특징 벡터를 확정해야 정해진다.

김천김밥축제 수치(2만→10만)는 언론 보도에서 온 것으로 원자료 확인 전이지만, **제품이 그 숫자에 의존하지 않는다** — 배경 설명일 뿐이고 판정은 실측 배수로 한다.

> **추측으로 적은 기대값은 eval 이 아니라 또 하나의 암묵지다.**
> Day 2에 특징 벡터를 확정한 뒤 01·08의 정답 라벨을 채운다.

## 쓰는 법

1. 필요한 줄을 골라 작업 지시의 `## 완료 조건`에 그대로 붙인다
2. 에이전트가 읽고 스스로 돌려본 뒤 스스로 고친다
3. 통과하면 커밋. 커밋 하나 = 지시 하나 = 되돌리기 지점 하나

지금은 손으로 돌린다. 자동화는 케이스가 20개를 넘을 때 생각한다 — *"평가 프레임워크를 고르다 이틀을 쓰는 팀이 매번 나옵니다."*
